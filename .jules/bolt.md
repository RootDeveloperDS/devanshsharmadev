## 2024-08-06 - Layout Thrashing Avoidance & Stale State Risks
**Learning:** Optimizing `getBoundingClientRect()` by caching it and updating on window resize/scroll can backfire. If an element's position changes due to other factors (CSS animations, late-loading content) rather than window events, the cached bounds become permanently stale, breaking mouse-tracking animations and causing visual bugs. Additionally, reading layout metrics during a fast-firing `scroll` event can introduce layout thrashing across the entire page, directly countering the intended performance gain.
**Action:** Always favor debouncing layout reads within an animation frame inside high-frequency events (like `mousemove`). When selecting optimizations to meet the "two-edit rule," lean toward safe state memoization and hoisting static calculations out of the render cycle.
